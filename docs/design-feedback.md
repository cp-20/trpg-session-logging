# デザイン指摘台帳

利用者（プロダクトオーナー）から受けた UI の指摘を、再発させないための規則に直して並べたもの。
出典は `.live-review/notes.json`（画面上のコメント 100 件）と、AI エージェントへの長文指示 4 本（2026-11-17）。

- 規則の本文は [DESIGN.md](../DESIGN.md)、汎用の原則は [design-principles](../.agents/skills/design-principles/SKILL.md) にある。ここは「なぜその規則があるか」の記録。
- **検査**の列は、規則を守らせる仕組み。
  - `lint:` `scripts/lint-design.ts`（ソースを検査。`pnpm run lint`）
  - `audit:` `e2e/design-audit.ts`（描画後の画面を検査。`pnpm run test:e2e`）
  - `型` 部品の型で書けなくしているもの
  - `部品` 共通部品に組み込んでいて、使えば自然に守れるもの
  - `目視` 機械で判定できず、`node scripts/ops.ts review` のスクリーンショットで確かめるもの
- 新しい指摘を受けたら、ここに 1 行足し、可能なら `lint:` か `audit:` に落とす。

## 1. 文言

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 「日付をクリックして予定や候補日を追加」「候補日を複数提示して…集められます」などの説明はいらない。「自明な説明やめろって言ったよね？」 | 操作を見れば分かることを文章で説明しない | `lint:self-evident`（〜できます。）、`audit:banned-copy`、`目視` |
| `.ics` みたいなユーザーに関係ない技術の詳細を書かない | 技術用語・ファイル形式名を文に出さず、利用者がすることを書く | `lint:jargon`、`audit:banned-copy` |
| 「CC<= を検出」「ログから推定」などシステム都合の文章 | 解析の内部事情を出さない | `lint:AI_SLOP_PATTERNS`、`audit:banned-copy` |
| 「セッションをまたいで育つ」などの謎ポエム、「港町キャンペーン全3話を進行中」 | 詩的な副題・作り話の説明を書かない | `lint:AI_SLOP_PATTERNS` |
| 「KP」は CoC 特有／「進行」と表記揺れ | 全システム共通で「GM」に統一。用語集を `docs/glossary.md` に置く | `lint:KP:`、`lint:進行ラベル`、`audit:banned-copy` |
| 「進行メモって何？どこから取得するの？」 | 出所の分からない情報や造語を出さない | `lint:AI_SLOP_PATTERNS` |
| システム名を CoC7 のように省略しない | 正式名を `SysBadge` で出す | `lint:BANNED_ABBREV`、`部品:SysBadge` |
| 「何のアップロード？？」「どういう形式のテキスト？？」 | 入口では何を入れると何が残るかを具体的に書く | `目視` |
| 「メンバー限定の意味が謎」 | 共有範囲は `SCOPE_META` の名前と説明をセットで出す | `部品:ScopeLabel / SCOPE_META` |
| 「3時間2分」と「3h2m」が混在 | 時間は `fmtDur` だけで書く | `lint:fmtDurShort` |
