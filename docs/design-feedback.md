# デザイン指摘台帳

利用者（プロダクトオーナー）から受けた UI の指摘を、再発させないための規則に直して並べたもの。
出典は `.live-review/notes.json`（画面上のコメント 100 件）と、AI エージェントへの長文指示 4 本（2026-11-17）。

- 規則の本文は [DESIGN.md](../DESIGN.md)、汎用の原則は [design-principles](../.agents/skills/design-principles/SKILL.md) にある。ここは「なぜその規則があるか」の記録。
- **検査**の列は、規則を守らせる仕組み。
  - `lint:` `scripts/lint-design.ts`（ソースを検査。`pnpm run lint`）
  - `audit:` `e2e/design-audit.ts`（描画後の画面を検査。`pnpm run test:e2e`）
  - `型` 部品の型で書けなくしているもの
  - `部品` 共通部品に組み込んでいて、使えば自然に守れるもの
  - `目視` 機械で判定できず、`node scripts/ops.ts review` のスクリーンショットで確かめるもの
- 新しい指摘を受けたら、ここに 1 行足し、可能なら `lint:` か `audit:` に落とす。

## 1. 文言

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 「日付をクリックして予定や候補日を追加」「候補日を複数提示して…集められます」などの説明はいらない。「自明な説明やめろって言ったよね？」 | 操作を見れば分かることを文章で説明しない | `lint:self-evident`（〜できます。）、`audit:banned-copy`、`目視` |
| `.ics` みたいなユーザーに関係ない技術の詳細を書かない | 技術用語・ファイル形式名を文に出さず、利用者がすることを書く | `lint:jargon`、`audit:banned-copy` |
| 「CC<= を検出」「ログから推定」などシステム都合の文章 | 解析の内部事情を出さない | `lint:AI_SLOP_PATTERNS`、`audit:banned-copy` |
| 「セッションをまたいで育つ」などの謎ポエム、「港町キャンペーン全3話を進行中」 | 詩的な副題・作り話の説明を書かない | `lint:AI_SLOP_PATTERNS` |
| 「KP」は CoC 特有 | 進行役は「進行」と書く | `lint:KP:`、`audit:banned-copy` |
| 「進行メモって何？どこから取得するの？」 | 出所の分からない情報や造語を出さない | `lint:AI_SLOP_PATTERNS` |
| システム名を CoC7 のように省略しない | 正式名を `SysBadge` で出す | `lint:BANNED_ABBREV`、`部品:SysBadge` |
| 「何のアップロード？？」「どういう形式のテキスト？？」 | 入口では何を入れると何が残るかを具体的に書く | `目視` |
| 「メンバー限定の意味が謎」 | 共有範囲は `SCOPE_META` の名前と説明をセットで出す | `部品:ScopeLabel / SCOPE_META` |
| 「3時間2分」と「3h2m」が混在 | 時間は `fmtDur` だけで書く | `lint:fmtDurShort` |

## 2. 成功通知・状態表示

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 「✓ 反映しました」の表示がダサすぎる。画面で分かるならそれでよい | 成功は画面の変化で伝える。通知文を出さない | `型:InlineNotice は pending / error のみ`、`lint:AI_SLOP_PATTERNS`、`audit:banned-copy` |
| 「11月17日(火) を空きに戻しました」こういうのやめろ！！！ | 同上 | 同上 |
| 「コピー済み」はボタンに直接出して（chip ではなく） | 一時的な結果はボタン自身の表示を変える。幅を固定して CLS を出さない | `部品:CopyBox` |
| CLS が起きている | 状態表示で周囲をずらさない | `目視` |
| toast を雑に使わない | 結果は操作した場所に出す | `lint:toast` |
| サーバー反映を待つものは optimistic update + 読み込み中は disabled | 楽観的に反映し、待つ間は操作を止める | `目視` |

## 3. 見せる情報の選び方

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 「候補 5件」見たら分かるし意味のない数字を見せないで | 数えれば分かる件数・回数を出さない | `目視` |
| 発言件数・セッション回数・最終日は一覧にいらない | 一覧は識別に必要な情報だけ | `目視` |
| ナビの件数バッジ | ナビに件数を出さない | `audit` のナビ項目の完全一致 |
| ログ未添付を一覧に出さない | 例外状態でも一覧で判断に使わないなら出さない | `lint:ログ未添付` |
| 「この日付、左の情報と重複してる」「システム選択してたらシステム表示は自明」 | 同じ情報を同じ画面に二度出さない | `部品:SessionRow の context`、`目視` |
| 「11月7日(土)・8日(日)（2日間…）クトゥルフ… メンバー限定」が雑に並べただけ | 見出しのメタ情報は「いつ」と「何を」の 2 行に分ける | `部品:PageHead + .meta`、`目視` |
| 「公開」をどこに置くかもっと慎重に | 共有範囲は共有操作の近くに置く | `目視` |
| 統計はいらない／概要に統合 | 補助情報は独立タブにせず概要の下に置く | `目視` |
| ダイスの表示はいらんかも（参加者欄） | 参加者欄は人とキャラクター、SAN の増減だけ | `目視` |
| 個人ページに連携サービスや大きな数字はいらない | プロフィールは人となりと一緒に遊んだ記録 | `目視` |
| 卓の作成者より、メンバーが重要 | 卓はメンバーを先に見せる | `目視` |
| 卓の一覧に日程調整は入れない | 卓一覧の「次回」は確定した予定だけ | `目視` |
| 時系列が linear じゃない／新しいものが上 | 時系列は新しい順にそろえる（予定は近い順） | `目視` |

## 4. 部品の形

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 「何でもかんでも chip で見せすぎ」「chip UI 好きだね」「何の意味がある chip？」 | 枠つき丸型の小札を使わない。情報は文字、例外状態だけ `Tag` | `lint:chip`、`部品:SysBadge（点＋名前）` |
| 「安直にラベルを付ければいいと思うなよ」 | 「シナリオ:」のような見出しラベルを付けず、アイコンや配置で示す | `目視` |
| 「カードがダサすぎる」 | 面を入れ子にしない。一覧は行で並べる | `audit:no-nested-surface`、`lint:card` |
| native select をやめて | `Select` を使う | `lint:select`、`audit:no-native-select` |
| Select を押したときに縮む | Select は押下時に縮めない | `部品:Select`（CSS） |
| Select の中に横スクロールバー | メニューは横にはみ出さない | `部品:Select` |
| 「ここ Select UI なのか？？」 | 選択肢が少なく見比べたいものは `Seg`、多いものは `Select` | `目視` |
| ファイル選択だけ英語 | ファイル入力は `<label>` で包んだ `sr-only` | `lint:file-input` |
| title 属性を安易に使わない | ネイティブのツールチップを使わない | `lint:title`、`audit:no-native-title` |
| sparkle アイコン、謎の背景色 | 意味のない装飾をしない | `lint:IconSparkles` |
| ×が小さすぎる | アイコンボタンは 40px 四方 | `部品:.icon-btn`、`audit:min-target-size` |
| UI が全体的に小さい | 文字は 12px 以上、操作は 40px 前後 | `lint:micro-font`、`audit:min-font-size-12` |
| ボタンの height がそろっていない | ボタンの高さは `.btn` / `.btn-sm` の 2 種類 | `lint:btn-modifiers` |
| プラスアイコンが細い、余白が雑 | 主ボタンのアイコンは太め、余白は `.btn` に任せる | `部品:.btn-primary svg` |

## 5. ボタンとホバー

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 副ボタンは輪郭が分かるように（薄い背景か枠） | 副ボタンは枠つき、低優先度は塗り | `lint:btn-modifiers`（btn-ghost 禁止） |
| outline のホバーで白黒反転させない／色が変わりすぎ | ホバーで面の色はほぼ変えず、枠だけ濃くする | `部品:styles.css`、`lint:btn-color-override` |
| outline の枠が強すぎ、ホバー時は薄すぎ | 静止時の枠は控えめ、ホバーで枠をはっきり | `部品:styles.css` |
| ホバーで border の角が欠ける | 行のホバー背景は角丸を保つ | `部品:.row-interactive` |
| active の色が強すぎ | 現在地は薄い主色の面＋主色の文字 | `部品:shell` |

## 6. 画面の構成と流れ

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 何でもかんでもモーダルにしない | よく使う操作はその場で。モーダルは確認・まれな設定・集中が要る入力だけ | `目視` |
| 普段使わないものは隠す | まれな操作は `Menu`（…）や開閉にしまう | `部品:Menu` |
| 確定した予定と日程調整を分ける／カレンダーからの追加は確定した予定 | 予定の追加と日程調整は別の入口 | `目視` |
| 予定に参加可否を答えるのではなく、アクティブな日程調整と今後の予定を出す | カレンダーは「返事待ち → 予定 → 月表示」 | `目視` |
| 開始時刻だけ入れて、時間は別に | 予定は開始時刻＋所要時間で入れる | `目視` |
| 個別予定を Google カレンダーに登録させるのではなく購読させる | カレンダー連携は購読リンク 1 本に寄せる | `目視` |
| カレンダーのホバーで情報を出したい／もっとゆっくり出して | 予定の詳細は `HoverCard`（待ち時間つき） | `部品:HoverCard` |
| 卓フィルタはカレンダーにドッキング | 絞り込みは対象の一覧のすぐ上に置く | `目視` |
| 土曜は青、祝日を反映 | 曜日色は `weekdayTone` | `部品:DateBlock / weekdayTone` |
| 戻るが一番下にしかない | 長い入力は戻る／確定を画面下に固定 | `目視` |
| 参加者の割り当ては前の画面と統合 | 記録の確認は 1 画面で完結させる | `目視` |
| 自動で処理した結果を見せた上で手で直せるように | 推定値は表示して、その場で修正できる | `目視` |
| 「どこにいてもスラッシュでここに来る」のをやめる | 単一キーのショートカットを置かない | `目視` |
| 感想はブログのコメントではなく各自が一言 | 感想は参加者ごとに 1 件 | `目視` |
| 編集中に編集している感がない／自分のキャラしか編集できないのが分かりにくい | 編集状態は見た目で切り替え、権限外は出さない | `目視` |
| セッションを開くは共有ページの上部ではない | 共有ページは読むためのページ。管理操作を置かない | `目視` |
| 卓報告の「Xで投稿」をもっと強調、`#卓報告` はいらない | 共有の主操作を主ボタンに | `目視` |
| 共有ページのシナリオ名はリンクに | 参照している対象はリンクにする | `目視` |

## 7. テーマ

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 背景・カード・ホバーの色のトーンを暖色にそろえる | 地・面・線・ホバーを同じ色相で | `部品:tailwind.config.ts` |
| ダークモードの白が強すぎる | ダークの文字は柔らかい白 | `audit:dark-mode-soft-text` |
| ダークモードでモーダルの背景が白い | 面の色はテーマのトークンで | `lint:hex`、`部品:Modal` |
| ライトモードではサイドバーもライト | ナビの面はテーマに従う | `部品:shell` |
| ダークの主ボタンの文字が読みにくい（2026-11-18 自己検査で発見） | ボタン文字は 4.5:1 以上 | `audit:button-contrast` |

## 8. 作り方

| 指摘（要旨） | 規則 | 検査 |
|---|---|---|
| 指摘箇所だけでなく、同じように直せる場所を探す。機械的なルールに落とす | 指摘はこの台帳と lint / audit に反映する | この文書 |
| 共通部品と同じものを画面ごとに作らない（2026-11-18） | 共通部品は `ui.tsx` / `identity.tsx` にだけ置く | `lint:reserved-primitive` |
| ドメインに依存しない純粋関数は単体のファイルに | 書式・日付計算・取り込みは `src/lib/` に置きテストする | `目視` |
| ページ数を増やしすぎない | `src/pages` は 13 ファイルまで | `lint:MAX_PAGE_FILES` |
| JS を使わない | `.js` / `.mjs` / `.cjs` を置かない | `lint:no-js` |
